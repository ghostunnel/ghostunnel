Release candidate for v1.12.0.

## Highlights

* **Outbound HTTPS proxies with client certificate authentication.** Client mode can now reach the target through an HTTPS CONNECT proxy (`--proxy https://...`), verifying the proxy against `--proxy-cacert` (or `--cacert`) and optionally presenting a dedicated, hot-reloadable client certificate to the proxy via the new `--proxy-keystore` or `--proxy-cert`/`--proxy-key` flags. The HTTP CONNECT implementation is now in-tree and bounded by `--connect-timeout`. See the [outbound proxy docs](https://ghostunnel.dev/docs/networking/outbound-proxy/) (#840).
* **Idle timeout and rolling close timeout.** New `--idle-timeout` flag closes connections with no traffic in either direction, and `--close-timeout` now resets whenever data moves, so a slow but active response is no longer cut off after a half-close. See the new [timeouts docs](https://ghostunnel.dev/docs/networking/timeouts/) (#842).
* **TLS session invalidation on reload is now explicit.** Reloads have always invalidated server-side TLS sessions as a side effect of rebuilding the TLS configuration. That invalidation is now explicit and guaranteed: every reload (signal or `--timed-reload`) bumps a generation counter that outstanding session tickets are checked against, so a resumed connection can never outlive the reload that followed it. This also extends the behavior to the SPIFFE Workload API source, which does not reload from files and so previously did not take part in it (#841).
* **Native Prometheus metrics backend.** Metrics are now collected directly with `prometheus/client_golang` instead of `go-metrics` plus bridges. Metric names are unchanged, but timers are now histograms and some derived fields were dropped; see the [migration notes](https://ghostunnel.dev/docs/networking/metrics/#migrating-from-v111x) (#842).

## New Features

* **HTTPS CONNECT proxies.** `--proxy` accepts `https://` URLs. The connection to the proxy is wrapped in TLS, the proxy certificate is verified against `--proxy-cacert`, falling back to `--cacert` and then the system trust store, and the `CONNECT` request is sent inside that session. `--alpn` and the `--verify-*` flags continue to apply to the target, not the proxy (#840).
* **Proxy client certificates.** `--proxy-keystore` (PEM, PKCS#12, or JCEKS) or `--proxy-cert`/`--proxy-key` configure a client certificate for authenticating to an HTTPS proxy, independent of the credential presented to the target. It is reloaded alongside the main certificate on SIGHUP and `--timed-reload`, and the paths are covered by the Landlock sandbox (#840).
* **In-tree HTTP CONNECT dialer.** The `go.connect-proxy-scheme` dependency was replaced with an in-tree implementation. Credentials in the proxy URL are sent as basic proxy authentication, the whole `CONNECT` exchange is bounded by `--connect-timeout`, and proxy URLs are redacted in logs (#840).
* **Idle timeout.** New `--idle-timeout` flag (default `0s`, disabled) closes a connection when no data is transferred in either direction for the given duration. Traffic in either direction resets the clock, so a long download with a silent client is unaffected (#842).
* **Rolling close timeout.** After a half-close, `--close-timeout` is now an inactivity timeout on the surviving direction rather than a fixed deadline counted from the half-close. Data keeps the connection alive; it is reaped only after `--close-timeout` of silence. `--close-timeout=0` still closes immediately, and `--max-conn-lifetime` still caps everything (#842).
* **Session resumption bound to reload generation.** Server-side TLS session tickets are tagged with a reload generation and only accepted in the generation that created them. Resumed connections continue to reuse the access control decision from their full handshake (which is what makes resumption cheap), and a reload is now an explicit, enforced bound on how long that decision can be reused, regardless of certificate source. See [session resumption](https://ghostunnel.dev/docs/certificates/reloading/#session-resumption) (#841).
* **Metrics backend.** Ghostunnel now owns a single Prometheus registry and serves `/_metrics/prometheus` straight from it, with native histograms enabled on all timers. The JSON (`/_metrics/json`, `--metrics-url`) and Graphite (`--metrics-graphite`) outputs are produced from the same registry. New `conn.error` counter for I/O errors during data transfer. Graphite pushes now follow `--metrics-interval` (default `30s`) instead of a hardcoded one second, pushes to Graphite and `--metrics-url` are bounded by a timeout, and non-2xx responses from a `--metrics-url` receiver are logged as errors (#842).

## Bug Fixes

* **Timeout reaping no longer logged as copy errors.** Connections closed by `--idle-timeout`, `--close-timeout`, or `--max-conn-lifetime` are reported with the reason under connection logging (`closed by timeout: ...`) rather than as an `error during copy: i/o timeout`. They are still counted in `conn.timeout`, except for `--close-timeout=0`, which is an immediate close rather than a timeout (#842).
* **Fatal startup errors reported once.** Startup failures are now reported once by `main()` with full context instead of being logged at the failure site and then again on exit. They always go to stderr, and additionally to syslog or the Windows Event Log when `--syslog`/`--eventlog` is active (#842).
* **Credentials redacted in logs and errors.** Proxy and metrics URLs containing `user:password@` are redacted in startup messages and Landlock errors (#840, #842).
* **Windows `service install` rolls back on start failure.** If the freshly installed service fails to start or never reaches Running, the service registration and event log source are removed again so the install can be retried after fixing the problem (#842).
* **`--metrics-interval` validation.** A zero or negative `--metrics-interval` is rejected at startup instead of panicking in the metrics ticker (#842).
* **ACME retry logging.** Retry messages during initial ACME certificate issuance now go through Ghostunnel's logger, so they honor `--syslog`, `--eventlog`, and `--quiet` (#842).

## Code Quality Changes

* **Proxy teardown rewrite.** Timeout enforcement for proxied connections moved from per-socket deadlines into a single per-connection watchdog that owns idle, half-close, and lifetime deadlines, which is what makes the rolling `--close-timeout` and `--idle-timeout` possible (#842).
* **Consistent error and log messages.** Error messages and log lines across the codebase were normalized (lowercase, `unable to X` phrasing, quoted paths and user input, `%w` wrapping, sentinel errors) (#842).
* **More linters.** Enabled gosec, errorlint, errname, testifylint, thelper, forcetypeassert, unparam, depguard (banning `math/rand`), forbidigo (banning `log.Fatal`/`Panic`), and a set of low-noise correctness and modernization linters, and fixed everything they surfaced (#842).
* **PROXY protocol code split out.** PROXY protocol v2 header construction moved into its own file in the `proxy` package; no behavior change (#842).

## Testing Improvements

* **Race detector in CI.** New `test:race` target and CI job run the unit tests under the race detector, separately from the coverage-instrumented runs they are incompatible with (#842).
* **Outbound proxy tests.** New integration tests for HTTP and HTTPS CONNECT proxies, including PEM and PKCS#12 proxy client certificates, proxy certificate rejection, a silent proxy that never answers `CONNECT`, and reload with a broken proxy credential (#840).
* **Session resumption tests.** New integration tests verify that sessions resume within a generation and fall back to a full handshake after a reload, including when the CA bundle reload fails (#841).
* **Timeout tests.** New integration tests for `--idle-timeout`, rolling `--close-timeout` in both directions, `--close-timeout=0`, idle/close interaction, and `--max-conn-lifetime` during an active transfer (#842).
* **Metrics tests.** Unit test coverage for the new `metrics` package, plus integration tests for Graphite-only reporting and `--metrics-url` error handling (#842).

## Other

* **Documentation.** New pages for [outbound proxies](https://ghostunnel.dev/docs/networking/outbound-proxy/) and [timeouts and connection lifecycle](https://ghostunnel.dev/docs/networking/timeouts/), session resumption documented under [reloading](https://ghostunnel.dev/docs/certificates/reloading/#session-resumption), and a [migration section](https://ghostunnel.dev/docs/networking/metrics/#migrating-from-v111x) in the metrics docs listing exactly which Prometheus, Graphite, and JSON fields changed (#840, #841, #842).
* **Dependency cleanup.** Removed `rcrowley/go-metrics`, `square/go-sq-metrics`, `cyberdelia/go-metrics-graphite`, `deathowl/go-metrics-prometheus`, and `wrouesnel/go.connect-proxy-scheme` as direct dependencies (#840, #842).
* **Go API changes.** For importers of the `proxy` package: `proxy.New` now takes a `proxy.Timeouts` struct, and the metrics handles moved to the new `metrics` package (#842).

## New Flags

| Flag | Description |
|------|-------------|
| `--idle-timeout` | Close a connection when no data is transferred in either direction for this long. Zero (default) disables it. |
| `--proxy-keystore` | Path to keystore with client certificate for authenticating to an HTTPS proxy (combined PEM, PKCS#12, or JCEKS) |
| `--proxy-cert` | Path to client certificate for authenticating to an HTTPS proxy (PEM with certificate chain) |
| `--proxy-key` | Path to private key for the proxy client certificate (PEM) |
| `--proxy-storepass` | Password for `--proxy-keystore` (PKCS#12 or JCEKS; optional for PKCS#12) |
| `--proxy-cacert` | Path to CA bundle for verifying an HTTPS proxy. Uses `--cacert` by default. |
